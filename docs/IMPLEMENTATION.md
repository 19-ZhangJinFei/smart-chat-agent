# 实现说明与课程对应

## 阅读顺序

先看 `backend/app/config.py` 和 `models.py`，再看 `memory.py`、`llm.py`、`tools.py`、`agent.py`，最后看 `main.py` 与前端 `App.vue`、`ChatPanel.vue`、`api/stream.js`。运行中的交互与源代码结合阅读。

第一课的七个演示在 `backend/demo_*.py`，包括SDK裸调用、LangChain对话、命令行流式、CourseInfo/BookInfo结构化抽取、手动历史、最小FastAPI。演示脚本在main入口才请求模型，不因测试导入产生费用。

第二课的工具与智能体在 `tools.py` 和 `agent.py`；第三课的意图分类、SSE、限流、评估与容器配置分别在 `llm.py`、`main.py`、`rate_limit.py`、`test_eval.py` 和根目录Compose。

## 一次对话怎样完成

Vue发送会话ID和问题，FastAPI验证长度并取得会话锁，然后读取业务历史。普通模式将系统提示、完整历史轮次和当前问题交给模型；智能体模式交给LangChain `create_agent`，模型提出工具调用，框架执行工具并把结果送回模型，直到得到最终回答。自动模式先用Pydantic Intent进行结构化分类，再走以上路径。

生成成功后才在同一个SQLAlchemy事务中写入用户问题、助手回答、工具元数据，并递增历史版本及更新时间。模型失败不写半轮记录。仅保存和展示本轮工具名称，不把工具标签拼入回答当成模型记忆。

## 为什么有两个SQLite文件

`smartchat.db`保存用户可见事实；`agent_memory.db`由SqliteSaver保存完整模型与工具检查点。业务历史版本与检查点版本一致时可续跑；普通模式增加历史、失败或上下文达到上限时，下轮智能体先删除旧检查点，再从成功业务问答重建。两个库不具备跨库原子事务，版本比较负责下一轮恢复。删除会话先清理官方delete_thread，再提交业务删除；失败返回错误。

默认模型上下文保留最近20个完整轮次、最多16000字符，完整展示历史仍保留数据库中。检查点重建去除过往工具中间步骤，保留用户可见问答；本轮工具调用与结果始终由框架成对管理。

## SSE与限流

普通模式POST流式接口发送 `data: {"delta":"..."}`，全部生成并落库后才发送 `[DONE]`。取消或错误丢弃部分结果。浏览器按网络块保留UTF-8解码和事件缓冲，不能对每块直接JSON.parse。自动与智能体模式使用完整响应。

滑动窗口按单调时钟记录每IP最近60秒的20次请求。第21次429含Retry-After，健康检查豁免；单worker内存状态重启清空。Nginx覆盖客户端转发头，Uvicorn只信任指定代理网段。这不是多实例共享限流。

## 相对教程的调整

| 调整 | 理由 |
|---|---|
| 统一code/message/data与HTTP状态 | Vue处理成功与错误一致 |
| AST加Decimal代替eval | 限定表达式并准确完成十进制运算 |
| 未知订单与城市明确缺失 | 防止编造业务信息 |
| 增加优惠券第五工具 | 课后练习与电商场景一致 |
| 版本校验和会话锁 | 处理模式切换、失败检查点和并发删除 |
| 成功后同事务保存一轮 | 避免孤立问题和部分流式内容 |
| 有缓冲的SSE解析 | 处理中文和跨网络块JSON |
| 动态未来日期 | 避免教程固定日期已过期 |
| 可配置宿主机端口 | 本机8080已有其他Docker项目，实际用8081 |

## 答辩中的概念

Function Calling是模型输出工具名与参数，Python执行真实函数；模型不直接执行任意代码。ReAct描述模型推理、动作与观察的循环，本项目使用create_agent负责循环，不额外实现一套调度器。持久记忆不是模型永久学会，而是重新传入数据库或检查点上下文。Docker镜像包含应用和依赖，挂载目录包含运行数据，两者生命周期不同。
